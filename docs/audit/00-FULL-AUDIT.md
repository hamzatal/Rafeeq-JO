# 1) التصميم — لماذا «مش عاجبك»؟ الجواب بالأرقام

إحساسك صحيح تماماً، وهذه ليست مسألة ذوق. حسبت نسب التباين (WCAG) للهوية الحالية، والنتائج تفسّر بالضبط ما تشعر به.

## 1.1 المشكلة الجذرية: الهوية الحالية «بنك»، وليست تطبيق طلاب

| الزوج اللوني | النسبة | الحكم |
|---|---|---|
| Navy `#002045` على أبيض | **16.25:1** | هذا تباين **أسود تقريباً**، ليس كحلي |
| Teal `#006A65` على أبيض | 6.46:1 | داكن أيضاً |
| Navy مقابل Teal (بينهما) | **2.51:1** | ← **هذه هي الكارثة** |

**التفسير:** إضاءة الكحلي 0.0146 وإضاءة التيل 0.1125. **كلاهما داكن**. لمّا تحط زر «أساسي» كحلي جانب زر «AI» تيل، العين تقرأهما **بنفس الوزن البصري** — فما في تراتُب (hierarchy) أبداً. النتيجة: كل شاشة تبدو ككتل داكنة متساوية الأهمية، فتحسّها «تقيلة» و«مش مرتبة». وهذا بالضبط ما تشوفه في `ui.tsx:StatCard` (بطاقة كاملة `backgroundColor: t.colors.primary` = كتلة شبه سوداء) وفي `home.tsx:pointsCard` وفي جداول الأدمن (`.data-table thead { @apply bg-navy }` — كل جدول له رأس أسود).

# 2) الأمان — ما يجب إصلاحه قبل الإطلاق

الباكند **أنظف من المتوقع**: صفر `$request->all()`، صفر SQL injection (كل `whereRaw` مُمَعلَم — مثال `CouponService.php:39`)، الملفات على قرص `private` خارج `public/` (`DriverDocumentService.php:19`)، كل تعديل محفظة داخل `transaction + lockForUpdate` (`WalletService.php:200-225`)، رؤوس أمنية على كل استجابة (`SecurityHeaders.php:22-40`)، و`.env` **غير مرفوع** للجيت.

لكن:

## 🔴 حرج 1 — استيلاء كامل على أي حساب برقم هاتف فقط

`config/otp.php:15-20`:
```php
'debug_return_code' => env('APP_ENV') === 'production' ? false : (bool) env('OTP_DEBUG_RETURN_CODE', true),
'universal_code'    => env('APP_ENV') === 'production' ? null : env('OTP_UNIVERSAL_CODE'),
```
`OtpService.php:68` → `return config('otp.debug_return_code') ? $code : null;`
ويُعاد للعميل في: `AuthController.php:35, 70, 82, 155` و`ProfileController.php:46` كـ `'otp_debug' => ...`

**الخطر:** الحرس الوحيد هو **مقارنة نصية حرفية** `=== 'production'`. أي قيمة `prod` أو `Production` أو `staging` تُبطله، **والافتراضي `true`**. حينها: استدعِ `request-otp` برقم أي مستخدم ← الكود يرجع لك **في نفس الاستجابة** ← دخول كامل. إضافةً لـ `universal_code` (`OtpService.php:79-84`) الذي يقبل أي رقم هاتف.

**الإصلاح:** احذف `otp_debug` من كل الاستجابات نهائياً؛ استخدم `app()->isProduction()`؛ واجعل السلوك fail-safe (الافتراضي `false`) + أضف تحققاً عند الإقلاع يرفض التشغيل إذا `APP_ENV` غير معروفة.

## 🔴 حرج 2 — أكواد OTP + أرقام الهواتف في اللوجات

`Infrastructure/Sms/LogSmsGateway.php:15-31`:
```php
Log::info('[SMS:LOG] Outbound message', ['to' => $to, 'message' => $message, ...]);
```
والرسالة تحتوي الكود نصاً (`OtpService.php:137`). وأخطر: `FallbackSmsGateway.php:26` يسقط لمزوّد بديل عند الفشل — لو كان البديل في الإنتاج هو `LogSmsGateway`، **كل أكواد المنصّة تُكتب في `storage/logs`**.

**الإصلاح:** لا تسجّل `message` أبداً (سجّل `reference` + طول الرسالة فقط)؛ واستثنِ `LogSmsGateway` من سلسلة الـ fallback في الإنتاج بشكل صريح.

## 🟠 عالٍ 3 — Race condition مالي على سحب أرباح الكباتن

`Modules/Payouts/Services/PayoutService.php:73-99` (`approve`) — **بلا transaction وبلا `lockForUpdate`**، والتحقق `if (! $payout->isPending())` يجري على موديل غير مقفول. و`reject` (`:101-142`) داخل transaction **لكن بلا قفل**.

**السيناريو:** طلبان متزامنان (approve + reject) يمرّان كلاهما ⇒ الكابتن يُعاد له المبلغ في محفظته (`:112-118`) **و** يُعلَّم الطلب كمدفوع. خسارة مالية مباشرة.

**الإصلاح:** `PayoutRequest::whereKey($id)->lockForUpdate()->firstOrFail()` داخل `DB::transaction` في كلا الدالتين.

## 🟠 عالٍ 4 — مفاتيح الخرائط مكشوفة بلا مصادقة

`routes/api.php:71-84` → `GET /api/v1/config` **عام**، يُعيد:
```php
'key' => (string) config('services.maps.google_key', ''),
'mapbox_token' => (string) config('services.maps.mapbox_token', ''),
```
ونفس المفتاح يُستخدم من الخلفية (`Infrastructure/Maps/MapsService.php`). لو لم يكن مقيّداً بـ referrer/package ⇒ سرقة مفتاح + فاتورة Google على حسابك.

**الإصلاح:** مفتاحان منفصلان (واحد مقيّد للعميل، وواحد للسيرفر لا يُنشر أبداً) + قيود Google Cloud إلزامية.

## 🟠 عالٍ 5 — اعتماد آلي لدفعات CliQ بناءً على صورة

`PaymentService.php:188-228` → عند `decision === 'matched'` من GPT‑Vision (`PaymentVerificationService.php:115-136`, `confidence >= 80`) **يُعتمد الدفع تلقائياً** ويُضاف رصيد حقيقي.
مخفَّف جيداً (بصمة صورة `image_hash`، فهرس فريد على `bank_reference`، أعلام احتيال تُلغي الاعتماد) — لكن **إيصال مُلفَّق مقنِع = مال حقيقي**.

**الإصلاح:** سقف مبلغ للاعتماد الآلي (مثلاً 20 د.أ)، وما فوقه مراجعة بشرية إلزامية.
