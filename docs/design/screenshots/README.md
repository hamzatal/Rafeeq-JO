# Screenshots

Four folders, three different jobs. They were accumulating without an index, which is
why they read as clutter.

| Folder | What it is | Regenerated by |
| --- | --- | --- |
| `compare/` | **The one that matters.** Eight pairs — `NN-name-reference.png` is the approved sheet rendered at 1280×820, `NN-name-live.png` is the running route at the same size. Same viewport, same scale, so a difference in the pair is a real difference. | `scripts/screenshots.sh admin` |
| `admin/` | Every dashboard route, one file each, for reviewing coverage. `index.json` maps file → route. | `scripts/screenshots.sh admin` |
| `student/`, `driver/` | The two Expo apps, exported with `--dev` and captured with the dev overlay suppressed. | `scripts/screenshots.sh student` / `driver` |

## What is the specification

`docs/design/src/0X-*.html` — **the sheets, as text, in the repository.**

`docs/design/v2/*.png` are renders OF those sheets. They are convenient to look at and
useless to build from: a picture carries colour, radius and spacing, but it cannot state
that a table has eight columns named «الطلب … الحالة», or that a header pairs «تصدير CSV»
with «دعوة كابتن». Every design gate before `check:parity` compared the code to itself,
so the dashboard sat at 25% of the sheets' required elements while all of them passed.

`npm run check:parity` reads the HTML and fails the build per screen. Start there, not
here — these images show you the result, they do not define it.
